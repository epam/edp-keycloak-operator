## What This Is

A Kubernetes operator that configures existing Keycloak instances.

## Architecture

### Layer Overview

```
cmd/main.go
  └── registers all controllers with controller-runtime manager

api/v1/          — CRD type definitions (spec + status structs, webhooks)
api/v1alpha1/    — Alpha CRDs: ClusterKeycloak, ClusterKeycloakRealm, KeycloakOrganization

internal/controller/{resource}/
  ├── reconciler.go   — Reconcile() entry point, fetches K8s resource, drives chain
  └── chain/          — Sequential handler steps (chain of responsibility pattern)

internal/controller/helper/ — Shared: Keycloak client factory, finalizers, failure tracking

internal/webhook/v1/ — Admission webhooks: KeycloakClient (defaulting, validation), KeycloakRealm and KeycloakRealmGroup (validation)

pkg/client/keycloakapi/  — oapi-codegen generated Keycloak client

config/          — Kustomize manifests (crd, rbac, manager, webhook, certmanager, prometheus, etc.)
deploy-templates/ — Helm chart: values.yaml, templates/, crds/, _crd_examples/; README auto-generated by helm-docs
bundle/          — OLM bundle manifests for OperatorHub publication

tests/e2e/       — KUTTL test suites (one directory per scenario, e.g. helm-success-path); run with make e2e on kind
```

### Keycloak Client

`pkg/client/keycloakapi/` — oapi-codegen generated client wired through resty HTTP client (auth, retries, TLS). Key files:
- `keycloak_client.go` — `KeycloakClient`, constructor `NewKeycloakClient(ctx, url, clientId, ...opts)`, options pattern, resty-backed `httpClient`
- `groups.go`, `roles.go`, `clients.go`, `users.go` — resource-specific method groups
- `generated/client_generated.go` — ~58k lines of oapi-codegen output; do not edit manually

## Development Workflow

### Prerequisites
Go 1.26, Docker, kubectl, kind, make

### Build & Run
```
make build                  # compile binary
go run cmd/main.go          # run locally (needs WATCH_NAMESPACE, OPERATOR_NAMESPACE env vars)
```

### Testing
```
make test                                            # unit tests
TEST_KEYCLOAK_URL=http://localhost:8086 make test    # unit + integration
make start-keycloak                                  # starts Keycloak on port 8086 via Docker
make e2e                                             # kind-based KUTTL e2e tests
```

### Linting
```
make lint-fix # run golangci-lint (config: .golangci.yaml) with auto-fix where possible
```

### Code Generation
```
make generate                                               # DeepCopy methods (kubebuilder markers)
make manifests                                              # CRDs, RBAC, webhooks → config/
make mocks                                                  # test mocks via mockery
make generate-keycloak-go-client                            # download the Keycloak OpenAPI spec and regenerate the client (rare)
```

## Conventions

### CRD scope
Each Keycloak object has one owner: the CR of its kind. A CR embeds only what Keycloak deletes with it, except nested objects of its own kind (separate CR with a parent reference). Anything else it names is a reference: link or unlink it, never create, update or delete it. New lookups fail on a missing referent with an error naming the owning CRD. A field that writes a referent is a leak: deprecate it.

### Deprecating a field
`Deprecated:` paragraph on the field and on code that exists only for it; tests use `//nolint:staticcheck // reason`. Admission warning of at most 120 characters.

### Adding a new chain handler
1. Create `internal/controller/{resource}/chain/my_step.go` implementing the handler interface.
2. Wire it into `chain/chain.go` in the correct call order.
3. Add a `_test.go` alongside it; use Ginkgo + Gomega.

### Reconciliation idempotency
Skip Keycloak writes when actual state matches the spec; track `status.observedGeneration` and force writes on generation change so spec removals propagate. Never delete-and-recreate child resources — diff by name (reference: `internal/controller/keycloakclientscope/chain/`).

### Sensitive values
A secret value comes from the spec or a Secret it names as `$name:key`; resolve refs through `pkg/secretref` on a copy of the spec map. The resolved value lives in the write body only: keep it out of the CR, status, events, logs and errors.

Keycloak returns `keycloakapi.MaskedSecretValue` on GET for secret-typed keys and for every key the provider does not declare as non-secret. Skip a key in the no-op compare when the raw spec value is a secret ref or the fetched value is the sentinel; compare the rest as a subset. The sentinel is the key list; a hand-kept list goes stale on the next provider or Keycloak release.

Build the write body from the resolved spec, so a forced write repairs the masked drift the compare cannot see. Force on generation change and on `status.configSecretsHash` change: `secretref.ValuesHash` over version tokens, stamped even when the write is skipped. A handler that resolves refs without the hash misses Secret rotation.

The idempotency suite for such a kind carries one masked key and one ref-backed key, and asserts a write on change and no write on settle.

### Optional list fields
`absent` = the resource does not manage that facet, leave Keycloak alone. `[]` = managed, clear every entry. `[a,b]` = managed, exactly a and b. Type such a field `*[]T`; a plain `[]T` cannot express the distinction, and the operator's own full-object `Update` erases an explicit `[]` from etcd. Older plain-slice fields still clear on omission — convert one when you touch it.

A sweep is a two-way diff and cannot tell "not mentioned" from "remove". Check nil before reading live state. Key an orphan sweep off "mentioned in spec", not "has a list", or the sweep undoes the nil check.

### Never edit generated code
`pkg/client/keycloakapi/generated/client_generated.go` is auto-generated — do not edit manually.
`pkg/client/keycloakapi/openapi/openapi.yaml` is downloaded from the Keycloak release in `KEYCLOAK_VERSION` (Makefile) — do not hand-edit it either. To change the client, bump that version and re-run `make generate-keycloak-go-client`.

### Scaffolded RBAC helper roles
`kubebuilder create api` scaffolds `*_admin_role.yaml`, `*_editor_role.yaml` and `*_viewer_role.yaml` per CRD, once. `make manifests` never regenerates them — controller-gen only writes `config/rbac/role.yaml` from the `+kubebuilder:rbac` markers.

Do not ship an admin or editor role for a kind whose spec pairs a Secret reference with an author-controlled destination (GHSA-wj3g-w873-xwg7); write access to such a kind grants indirect read of any Secret reachable by the operator. Keep the viewer role, delete the scaffolded admin and editor files, and drop their `config/rbac/kustomization.yaml` entries.
